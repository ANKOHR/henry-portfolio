Autonomous QA Engineer

AQE crawls an application over HTTP, maps pages and forms, derives request tests, executes them, and produces reproducible reports with the requests behind each finding.

Problem

The problem

A list of URLs alone does not capture the form fields, links, or required page elements that a request test should check. AQE builds a small site map and uses discovered page structure to create a test catalogue that can be run against a fixture app or an HTTP endpoint.

Design

Design

The explorer fetches pages and uses Python's HTMLParser to record same-origin links, form methods and fields, and declared required elements. The generator turns that map into cases such as field validation, required-element checks, and link requests. The executor sends HTTP requests and evaluates declared status, content, and timing conditions. Reporting groups failed outcomes and includes the exact request details needed to reproduce them.

Engineering decisions

Engineering decisions

The boundary is HTTP, not a browser automation stack. Page snapshots are saved as HTML bytes; AQE does not execute JavaScript, render a visual page, drive a browser, or take screenshots. Fixture apps include a clean control and a buggy version with planted behavior, so output can be checked against known expectations without connecting to a live service.

What the tests verify

What the tests verify

Tests check that exploration records the fixture pages, forms, and broken link; depth limits and invalid base URLs; catalogue generation from required elements and edge inputs; deterministic generation; and execution against buggy and clean fixtures. They verify that the expected planted findings have concrete request evidence and that reports disclose the HTTP-only boundary.
