Agent Control Tower

Agent Control Tower turns a deterministic synthetic organization event stream into a dashboard of task activity, costs, permissions, approvals, outcomes, errors, and incidents.

Problem

The problem

An operations view is only useful if its summaries can be traced back to events. Agent Control Tower uses one event stream as the input for task rows, cost totals, approval state, and incident timelines, so the demo can show how those views relate without connecting to an organization.

Design

Design

Typed Event objects validate the event schema and timestamps. The state builder validates event relationships and derives current task, agent, cost, approval, and incident summaries from the stream. The dashboard renderer turns that aggregate state into deterministic HTML. Approval decisions are appended as new events with a decision, reason, operator label, and timestamp, then the pending queue is rebuilt from the resulting stream.

Engineering decisions

Engineering decisions

The event log is the durable input; aggregate state is recomputed when it is read. Decimal arithmetic keeps fixture cost totals explicit. Stable fixture IDs, timestamps, serialization order, and dashboard section order make repeated reports comparable. Approval actions in the demo require a pending approval and leave a reasoned audit entry rather than changing an external system.

What the tests verify

What the tests verify

The suite checks fixture labels and byte stability, malformed events and duplicate or unknown references, named agent and task validation, and hand-computed costs. It also checks task permissions and errors, approval decisions and queue updates, incident timelines, deterministic dashboard output, and CLI paths for ingest and reports.
