Agent Control Tower

Agent Control Tower turns a deterministic synthetic organization event stream into a dashboard of task activity, costs, permissions, approvals, outcomes, errors, and incidents.

Problem

The problem

An operations view is only useful if its summaries can be traced back to events. A cost total, an approval state, or an incident timeline means little if you cannot see which events produced it. Most dashboards compute each view separately, so the numbers can quietly disagree with each other and nobody notices.

Agent Control Tower derives every view from a single event stream: agents, tasks, approvals, incidents, and the dashboard page itself all read the same log. The demo shows how those views relate to each other without connecting to a real organization.

Design

Design

A deterministic fixture generator (towerctl/fixtures.py) writes events.jsonl. A schema validator plus cross-event checks (state.py) validate the stream. model.py owns the typed event contract: every JSONL record has exactly four top-level fields, event_id, timestamp, event_type, and data. Unknown fields are rejected.

The validated stream feeds two paths. The aggregate builder derives costs, tasks, agents, permissions, errors, outcomes, and incidents. Approval decisions are append-only approval.decided events that feed back into the builder. Five views (agents, tasks, approvals, incidents) plus dashboard.py render the result; the dashboard is a self-contained deterministic HTML page.

The simulated approval console accepts approve, reject, or edit, each with a mandatory reason and an optional --at timestamp, mapping to the stream decisions approved, rejected, and edited. A decision must reference a requested, still-pending approval. It is appended as a new event, and the pending queue is rebuilt from the resulting stream, so the audit trail is the stream itself.

Engineering decisions

Engineering decisions

Stream validation is strict: events must arrive in timestamp order, every tool.called event needs a matching cost.recorded event, referenced IDs must exist, and the validator reports the exact event ID and failed field. A malformed stream fails loudly at ingest instead of producing a plausible-looking dashboard.

Costs use exact decimal arithmetic, not floats, rendered to eight decimal places, with fictional rates (demo-text-small at $0.15/$0.60 per 1M tokens, demo-text-large at $2.00/$8.00). Running elapsed time is measured at the latest event timestamp rather than the wall clock, which keeps reruns deterministic. The runtime is Python standard library only, with no dependencies.

What the tests verify

What the tests verify

The suite holds 12 test functions in tests/test_towerctl.py. They check fixture labels and byte stability, malformed events, duplicate or unknown references, named agent and task validation, and hand-computed costs against the decimal arithmetic.

Further cases cover task permissions and errors, approval decisions and queue updates, incident timelines, deterministic dashboard output, and the CLI paths for ingest and reports.

Scope and evidence

Scope

It monitors nothing real and connects to no live systems. Every name, event, cost, permission, and price is fictional. The audit trail is a local demo artifact that authorizes no external action; the CLI prints this boundary and the dashboard shows it.

What exists as evidence: 12 event types, 5 severity levels (info, low, medium, high, critical), 4 top-level event fields, 2 fictional pricing tiers, and the 12-function test suite.
