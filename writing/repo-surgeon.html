Repo Surgeon

Repo Surgeon uses deterministic Python AST heuristics to build a local import graph, flag possible cycles, dead code, code smells, and test gaps, and assemble a staged plan with file and line evidence.

Problem

The problem

A repository review often starts with questions that are expensive to answer by hand: how modules connect, whether a cycle exists, where suspicious complexity concentrates, and which modules lack tests. Repo Surgeon turns those questions into review candidates that point back to source locations.

Design

Design

The scanner parses Python modules into ASTs and resolves local imports into a graph. Analysis walks from conventional entry points to flag unreachable modules and public functions, checks source for named smell patterns and thresholds, and matches modules or public function names to test files to identify possible gaps. Findings include evidence paths and line numbers. The planner orders candidate actions into a staged remediation list, and report renderers emit JSON, Markdown, or HTML.

Engineering decisions

Engineering decisions

The analyzers use local static evidence and keep separate categories for import structure, likely dead code, smells, and test-name coverage. They do not instrument runtime execution or infer whether a framework, plugin, reflection, generated file, or external caller uses a symbol. The report labels findings as heuristics and points reviewers to the underlying evidence before any change is made.

What the tests verify

What the tests verify

Tests use two generated repositories: one with planted cycles, unreachable modules, duplicate functions, an oversized module, a risky call, and test gaps, plus a small clean control. Assertions check graph paths, clean behavior, named evidence, finding order and effort, fixture determinism, output stability, and the visible static-heuristics notice.
