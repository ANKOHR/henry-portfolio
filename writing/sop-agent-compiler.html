SOP to Agent Compiler

SOPC compiles procedures written in its documented Markdown grammar into a versioned plan IR that can be verified, graphed, contract-tested, and simulated.

Problem

The problem

A procedure document can describe a workflow without making its control flow mechanically checkable. Branch targets can be missing, actions can be reachable without review, and retry behavior can be unclear. SOPC makes the input contract explicit: a source file declares the steps, metadata, permissions, and control-flow targets in a supported grammar.

Design

Design

The parser converts the grammar into typed Step and Plan objects. The model serializes a versioned JSON intermediate representation. A separate verifier checks references, decision conditions, retry and checkpoint rules, reachability, and whether consequential actions are guarded on every path. The CLI can then emit a deterministic SVG graph, generate a pytest contract module, or run the plan with a simulated executor that appends audit events.

Engineering decisions

Engineering decisions

Compilation is grammar-based, not open-ended language understanding. Decision expressions are recorded as text, while a run receives explicit boolean results keyed by that text. At a checkpoint, the simulator pauses until it receives an approve, reject, or edit decision; rejection and edits need a reason. Retries follow the plan's declared attempt and backoff policy. This keeps simulation inputs visible and repeatable.

What the tests verify

What the tests verify

The suite checks valid and malformed source parsing with file, line, and rule errors; stable IR serialization; named schema failures; and verifier rules for references, retries, conditions, checkpoints, and consequential actions on every route. Executor cases cover pause, approval, rejection, edits, retries, permission denial, and explicit condition results. Separate checks compare generated graphs and compilation output across repeated runs.
