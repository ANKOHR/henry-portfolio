PromptCI

PromptCI detects changed prompt content, evaluates only linked synthetic suites, compares deterministic fixture results and cost and latency estimates, then applies named release rules.

Problem

The problem

Changing a prompt can alter output quality, runtime estimates, and which release checks matter. PromptCI makes prompt changes the trigger for a local evaluation pipeline and stores a candidate separately from the last accepted release so a failed gate does not become the new baseline.

Design

Design

Prompts are canonicalized and hashed. Prompt versions and suite links live in JSON project files, alongside deterministic fixture providers and scoring data. A run compares current hashes with the release record, selects suites linked to changed prompts, and writes candidate results and a per-case diff. Named gate rules turn score, cost, and latency comparisons into a release decision. Accepting a candidate updates the release record; a failed gate preserves the existing record.

Engineering decisions

Engineering decisions

The pipeline skips evaluation when no prompt hash changed, while still emitting a candidate record that explains the no-change state. Fixture providers run locally and expose declared price and latency profiles; they make no provider request. This makes the release calculation repeatable and lets tests hand-check the comparison formulas without credentials or network dependencies.

What the tests verify

What the tests verify

The suite checks deterministic fixtures, changed-prompt trigger behavior, affected-suite selection, attribution for planted regressions, hand-calculated cost and latency deltas, release gate decisions, report content, and CLI flows. It also checks that accepted release state is not changed by a failed candidate and that the synthetic provider boundary is disclosed.
