BrowserBench Local

BrowserBench Local evaluates scripted agents against a static synthetic site using a DOM-backed simulator, deterministic task rules, partial-credit scoring, and evidence reports.

Problem

The problem

Browser tasks combine navigation, data entry, filtering, uploads, and decisions about conflicting or untrusted page content. A useful test fixture needs to preserve those state changes and score individual requirements while ensuring adversarial examples cannot trigger a real send or upload.

Design

Design

Task JSON declares a starting page, available actions, criteria, weights, and expected evidence. The simulator parses fixture HTML into a small element and page-state model, then applies actions such as fill, click, search, filter, and navigation. It records action history and visited pages. Scoring applies the task's named rules criterion by criterion and awards partial credit for satisfied parts. The report includes per-task scores and evidence.

Engineering decisions

Engineering decisions

The environment is deliberately static and synthetic. The benchmark represents browser state in its own DOM-backed simulator instead of controlling a browser or executing site JavaScript. Task files plant cases for form handling, search, uploads, ambiguous instructions, conflicting facts, and prompt injection. The scorer checks resulting local state, including whether a simulated send remained inactive.

What the tests verify

What the tests verify

Tests validate task schemas and scoring weights, fixture page safety and labels, action effects in the simulator, form validation, navigation state, upload confirmation, partial-credit arithmetic, and deterministic reports. Adversarial tasks verify that the scripted agent records conflicting sources or asks for clarification and leaves its local send state inactive. CLI tests also cover serving the fixture site on loopback.
