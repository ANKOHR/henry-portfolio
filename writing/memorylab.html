MemoryLab

MemoryLab compares six deterministic memory policies on the same synthetic recall episodes and reports task success, token use, retrieval accuracy, and fabricated recall counts.

Problem

The problem

Memory designs trade context size against retrieval and correctness. To compare them, MemoryLab gives each policy the same fixed episode stream and asks it the same recall queries under a declared token budget. The benchmark reports several outcomes so a compact context is not judged only by how much it stores.

Design

Design

The six policies are full context, lossy summary, token-overlap retrieval, episodic memory, structured state, and a hybrid. Each produces context items for the query. A shared budget selector admits items within the whitespace-token budget. The runner resolves planted facts and records answers, source fact IDs, context tokens, and query tokens. Metrics summarize correct answers and abstentions, retrieval accuracy on answerable questions, and values that differ from the active planted fact.

Engineering decisions

Engineering decisions

Fact histories have explicit set, correct, and expire operations, which gives the structured policy a defined state transition model. Retrieval is deterministic: token overlap uses normalized words and a stable ranking, while the hybrid combines policy outputs under the same budget. Token accounting is intentionally simple and hand-checkable. The fixture suite uses no random generator or model call.

What the tests verify

What the tests verify

Repository tests cover fixture loading, each policy's selection and answer behavior, runner outputs and metrics, token budgeting, corruption counts, and command and report behavior. Assertions compare the policy outputs and aggregate metrics against planted episode facts, so they test the implementation's fixture rules rather than model quality.
