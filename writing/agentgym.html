AgentGym

AgentGym runs deterministic scripted fixture agents through synthetic multi-step tasks, records tool events, and evaluates the resulting episodes with hidden rule-based graders.

Problem

The problem

A single task score hides how an agent got there. On a multi-step task with tool calls, partial progress, constraints, and persistent state, a score of 0.6 tells you nothing about which step went wrong or why. Without a durable event trail, debugging a failure means re-running the whole thing and hoping it fails the same way.

Re-running is only useful if the run is reproducible. AgentGym models the full evaluation loop over synthetic task fixtures: deterministic scripted agents, per-step checkpointing, and hidden rule-based graders, so an episode can be replayed and its event sequence, score, and failure classification compared byte-for-byte against the stored record.

Design

Design

Tasks are JSON files in agentgym/task_fixtures/. runner.py hands the scripted fixture agent (agents.py) an AgentView that contains only the task text and the declared tools, nothing else. The agent then calls synthetic tools from toolbox.py: search, read, write, calculate, and ask. Every call and every result becomes a deterministic event, and a checkpoint is persisted to disk after every step under .agentgym/episodes.

The hidden rule-based grader (grading.py) computes four named subscores from the recorded events: completion, correctness, efficiency, and constraint respect. taxonomy.py classifies failures and cites the triggering event ids, so a label like looping points at the exact events that caused it. reports.py renders the results as Markdown and HTML.

replay re-executes the fixture and verifies the regenerated event sequence, score, and classification against the stored episode byte-for-byte. tasks.py validates task JSON up front; malformed files fail with TaskValidationError naming the invalid field.

Engineering decisions

Engineering decisions

The fixed seed is 0 and fixtures use no random values, so repeated runs produce byte-identical episode files and scores. Reproducibility is a property of the design, not a hope about the environment.

Grader internals (the exact checks and weights) stay server-side and never pass through the agent interface, so a fixture agent cannot game a rubric it cannot see. A public fixture_spec.md documents the partial-credit behavior without exposing the rubrics. Grading consumes recorded tool events, never the agent's own claims about what it did.

Failure detection is mechanical where possible. Looping is defined as the exact same tool and input signature occurring 3 or more times. The permission_boundary fixture plants a permission failure and the looping_trap fixture plants a looping failure, so the taxonomy has known positives to catch.

What the tests verify

What the tests verify

The suite holds 21 test functions in tests/test_agentgym.py. They check task schema validation and unique IDs, hand-calculated partial scores, exactly what information is exposed through the AgentView, byte-identical repeated runs, per-step checkpoint durability, and resume equivalence with an uninterrupted run.

Further cases cover replay verification, event-linked failure labels for the looping and permission fixtures, report evidence, and the synthetic-only notice in the CLI and HTML report.

Scope and evidence

Scope

AgentGym evaluates scripted fixture agents, not AI models. All tasks, tool results, agents, and graders are synthetic. It benchmarks no live language models and touches no real environments.

What exists as evidence: 4 task fixtures (research_brief, clean_dataset, looping_trap, permission_boundary), 5 synthetic tools, 8 failure taxonomy categories (planning, retrieval, hallucination, tool_misuse, state_corruption, looping, permissions, execution), and the 21-function test suite.
