ResearchReplicator

ResearchReplicator extracts sourced setup fields from synthetic paper fixtures, creates a reproduction plan, tracks configuration edits, and compares deterministic CPU-emitted metrics with declared targets.

Problem

The problem

A reproduction plan should distinguish what a source says from what is missing. Filling gaps with plausible defaults makes the plan look complete while weakening its provenance. ResearchReplicator treats extraction, planning, configuration history, and comparison as separate steps over declared fixture documents.

Design

Design

The Markdown extractor finds setup fields and records where each value came from. Missing fields remain typed as unknown in the setup record and plan. The plan cites extracted values rather than inventing a full experiment. The tracker assigns an identity to each configuration and records JSON-pointer changes. A run can invoke only the synthetic repository emitted by the fixture command after checking its manifest and script hash; the metric emitter is a CPU stand-in. Comparison checks observed values against declared targets and tolerances, and the report presents the provenance and comparison state.

Engineering decisions

Engineering decisions

Unknown values stay unknown, including an undeclared tolerance or unit mismatch. Config IDs separate revisions, and the tracked diff explains why a new configuration differs. Before execution, the workflow verifies that the fixture script has not changed, then runs it with CPU-only flags. These choices make the demo auditable while keeping its evidence boundary explicit.

What the tests verify

What the tests verify

Tests check source citations for extracted fields, typed empty extraction when a fixture lacks an experiments section, and that absent hyperparameters remain unknown. Other cases cover ordered plans, deterministic fixture and plan output, configuration diffs, rejection of unmarked repositories or changed fixture scripts, tolerance acceptance and rejection, unknown comparison units, and the extract-to-report CLI path.
