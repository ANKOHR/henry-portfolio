ResearchReplicator

ResearchReplicator extracts sourced setup fields from synthetic paper fixtures, creates a reproduction plan, tracks configuration edits, and compares deterministic CPU-emitted metrics with declared targets.

Problem

The problem

A reproduction plan should distinguish what a source actually says from what is missing. Filling gaps with plausible defaults makes a plan look complete while destroying its provenance: a reader can no longer tell which values came from the paper and which were invented by the person writing the plan.

ResearchReplicator treats extraction, planning, configuration history, and comparison as separate stages over declared fixture documents. Each stage's output carries its own provenance, so an UNKNOWN in the final report can be traced back to the exact extraction step that failed to find it.

Design

Design

repkit extract (repkit/extract.py) parses a fictional Markdown paper into a typed setup record. Every extracted value is stored with its source as a {value, source_section} pair, and where the paper discloses nothing the field stays UNKNOWN. No defaults are guessed. The extraction schema tracks five hyperparameters: learning_rate, batch_size, epochs, seed, and optimizer.

repkit plan (plan.py) writes an ordered reproduction plan with JSON Pointer field_refs into the setup record, plus expected observations, controls, and checkpoints. repkit track (tracker.py) snapshots configs with diffs. repkit run executes only repos declared as synthetic fixtures, verifying the metric-emitter script hash first, then emitting deterministic stand-in numbers on CPU. repkit compare (compare.py) checks observed values against declared targets and tolerances. repkit report (report.py) renders Markdown or HTML. Persistent workflow artifacts live under .repkit, which is git-ignored.

Engineering decisions

Engineering decisions

Honesty is machine-readable: the extraction schema includes an honesty field stating the synthetic-only, no-training boundary, so the boundary travels with the data instead of living only in documentation.

The parser recognizes only explicit headings (Experimental Setup, Experiments, Experimental Details, with subsections for Datasets, Model, Hyperparameters, Metrics, Results). Anything else stays UNKNOWN. The tool would rather report ignorance than hallucinate structure from a heading it does not understand.

The runtime has no ML framework dependencies. The fixture script does no training and touches no GPU; it computes deterministic stand-in numbers from a JSON config, which is what makes runs comparable.

What the tests verify

What the tests verify

The suite holds 22 test functions across 5 files. test_extraction (4) checks source citations on extracted fields, typed empty extraction when a fixture lacks an experiments section, and that absent hyperparameters remain UNKNOWN. test_plan (4) covers ordered plan output. test_tracker_compare (8) covers configuration diffs, tolerance acceptance and rejection, and unknown comparison units.

test_cli (3) and test_fixtures_report_e2e (3) cover the extract-to-report CLI path end to end, rejection of unmarked repositories or changed fixture scripts, and deterministic fixture and plan output.

Scope and evidence

Scope

It never runs GPU training and never claims to have reproduced published results. All papers, repos, datasets, values, and results are invented; the fixture emitter computes deterministic stand-in numbers from a JSON config.

What exists as evidence: 4 fixtures (toy-paper.md, no-experiments-paper.md, missing-hyperparameters-paper.md, synthetic-repo/), 9 modules in repkit/, and the 22-function test suite covering extraction, planning, tracking, comparison, and reporting.
