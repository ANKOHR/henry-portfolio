ExperimentOS

ExperimentOS is a local CLI control centre for synthetic research workflows: it registers seeded synthetic datasets, runs formula-based metric simulations with checkpoints, evaluates hypotheses against observed minima, and requires every finding to cite the run it came from.

Problem

The problem

A small research workflow needs to preserve which dataset and configuration produced a metric series, allow a run to resume after interruption, and connect interpretations back to the evidence they came from. Reconstructing this from terminal history is unreliable: seeds get lost, configs drift, and findings detach from the runs that motivated them.

ExperimentOS stores those pieces locally in a workspace directory (.experimentos/ with datasets/, runs/, checkpoints/, reports/, overridable via EXPERIMENTOS_HOME or --home). Dataset registration records schema, row count, method, seed, and SHA-256 checksum. Runs write metrics.jsonl. Checkpoints capture configuration, metric prefix, step, and serialized RNG state. Hypotheses and findings append to JSONL ledgers.

The enforcement mechanism is what makes it interesting: findings.py raises UncitedFindingError for any finding that does not cite at least one existing run. The link from interpretation to data is machine-checked, not a matter of discipline.

Design

Design

A JSON config passes validation into simulator.py, which computes a closed-form base curve plus seeded Gaussian noise (random.Random(seed).gauss(0, noise_std) per step, one-based steps). Three profiles are available: exponential_decay (F + (L0 - F) * exp(-d * (i - 1))), plateau_then_drop, and linear (L0 + m * (i - 1)). Defaults are initial_loss 1.0, noise_floor 0.05, decay 0.05, noise_std 0.0, slope -0.01, and plateau_steps = steps/3. Setting noise_std to 0 yields the exact closed-form curve.

datasets.py registers synthetic CSVs (sample index, seeded uniform feature columns, weighted-sum target with seeded uniform noise) and records schema, row count, method, seed, and SHA-256 checksum: the same name and parameters produce identical bytes. runs.py writes metrics.jsonl per run; re-running the same normalized config under the same Python version yields byte-identical logs.

Checkpoints store the normalized config, metric prefix, step, and serialized RNG state including the Gaussian cache, so a resumed run is identical to an uninterrupted one. hypotheses.py evaluates predicates of the form metric <= number (supporting <, <=, >, >=, ==, !=) against the minimum observed value, returning a match or mismatch verdict. These verdicts are deliberately mechanical comparisons, not evidence about real models.

analysis.py compares runs per step and picks the best step by minimum loss with earliest-step tiebreak. The CLI (exo, also runnable as python -m experimentos) exposes eight commands: datasets, run, runs, checkpoints, hypothesize, findings, compare, report. Reports go in reports/, and the HTML report displays the synthetic-data boundary in a prominent banner.

Engineering decisions

Engineering decisions

Byte-identical reproducibility is an explicit design goal, achieved through fixed seeds, normalized configs, and serialized RNG state, including the Gaussian cache. That last part is the subtle one: Python's gauss() caches a second value internally, so resuming without the cache would diverge from an uninterrupted run. The quickstart demonstrates the guarantee concretely: 50 rows and 3 features at seed 17, a 40-step demo run at seed 23.

Run IDs and timestamps identify stored work but are kept outside the deterministic metric payload, so provenance metadata never contaminates the byte-identical comparison of results. This separation of identity from content is what makes the determinism claim checkable.

Hypothesis verdicts are deliberately mechanical: a predicate against the minimum observed value, returning match or mismatch. There is no statistical inference, no confidence interval, and no claim about what the numbers mean for a real model. The tool tracks the bookkeeping of an experiment; the interpretation stays with the researcher.

The UncitedFindingError is the sharpest design decision: a finding cannot exist in the ledger without citing a run. This turns "cite your evidence" from a norm into a constraint, and it is tested directly.

What the tests verify

What the tests verify

28 test functions across 6 files: test_cli (11), test_simulator_runs (5), test_hypotheses_findings (4), test_datasets (3), test_checkpoints (3), test_analysis (2). They cover simulator determinism, checkpoint and resume equivalence, dataset generation, hypothesis and finding logic, analysis, and CLI flows.

The tests check seed-based dataset reproducibility and checksums, hand-calculated points for each curve family, byte-identical metric logs for repeated configs, checkpoint resume equivalence (resumed output equals uninterrupted output), the ability to extend a resumed run, and rejection of uncited findings. CLI cases cover dataset, run, checkpoint, hypothesis, finding, comparison, and report flows.

Scope and evidence

Scope

The project computes seeded synthetic metric curves from closed-form functions: it does not train models, load weights, evaluate real systems, or use ML frameworks. Registered datasets are generated synthetic CSVs, not collected data. Outputs are simulator outputs, not empirical research results, and the HTML report states this in a prominent banner.

What is verified with evidence is the bookkeeping machinery of reproducible synthetic experiments: deterministic dataset registration with checksums, byte-identical metric logs, exact checkpoint resume, mechanical hypothesis verdicts, and citation-enforced findings, all covered by 28 test functions. It is a control centre for synthetic experiment discipline, not a source of empirical claims.
