ExperimentOS

ExperimentOS is a local CLI for seeded synthetic datasets, formula-based metric runs, checkpoints, hypotheses, findings, and reports.

Problem

The problem

A small research workflow needs to preserve which dataset and configuration produced a metric series, allow a run to resume, and connect interpretations back to evidence. ExperimentOS stores those pieces locally so a synthetic experiment can be reconstructed from files rather than remembered from a terminal session.

Design

Design

Dataset registration records a seed, generated CSV, schema details, and checksum. A run config identifies the dataset, simulator profile, step count, and seed. The simulator computes a closed-form curve and uses a seeded random generator for declared noise. Metrics are appended as JSONL. Checkpoints capture run configuration, metrics, and random generator state; resume continues from that saved state. Hypotheses and findings are separate records that cite run IDs, and the CLI compares runs and renders reports.

Engineering decisions

Engineering decisions

The simulator exposes exponential decay, plateau-then-drop, and linear profiles rather than training a model. Random state is serialized in the checkpoint so resumed output can match an uninterrupted run. Run IDs and timestamps identify stored work but are kept outside the deterministic metric payload. A finding that lacks a valid run citation is rejected, which preserves a machine-checkable link from interpretation to data.

What the tests verify

What the tests verify

The suite checks seed-based dataset reproducibility and checksums, hand-calculated points for each curve family, byte-identical metric logs for repeated configs, checkpoint resume equivalence, and the ability to extend a resumed run. CLI cases cover dataset, run, checkpoint, hypothesis, finding, comparison, and report flows, including rejection of uncited findings.
