OpsPilot: how it works.

Typed workflow runtime, approval gates, idempotent ingestion, checkpoint replay, audit traces, and explicit failure handling.

Problem

Workflows that are known but manual

Operations teams can describe the steps, but still do them by hand. Quick scripts can send twice, skip an approval, or silently lose an event.

Constraints

What the design had to respect

Irreversible actions require a human decision. Re-ingesting an event must not start a duplicate run. Retries must not repeat side effects. Actions need an ordered, reviewable record.

Design

A typed workflow runtime

A workflow is a directed acyclic graph of typed steps. The runtime owns ordering, retries, approval gates, replay, and audit logging. Step code implements its declared logic.

Implementation

Idempotency, gates, and checkpoints

Incoming events use content-derived idempotency keys. Approval steps wait for a recorded decision. Checkpoints let a run resume after completed steps. Transitions record hashes, actor, and time; AI step latency and token cost are recorded.

Failure modes

What happens when a step fails

Duplicate events resolve to the existing record. Worker failures resume from a checkpoint. Malformed AI output is rejected by its declared schema. An unavailable approver leaves the run waiting.

Testing

60 backend tests and 100 synthetic eval cases

The backend suite covers ingestion, gates, replay, and audit ordering. A separate set of 100 labelled synthetic cases exercises routing and escalation behaviour.

Result

A prototype with a verified integration path

The Gmail OAuth path was verified end to end. OpsPilot is a prototype, not a customer deployment.

Commercial applicability

Fit one workflow to a real process

The service engagement scopes one client workflow, approval point, and audit record, then hands over the system and runbook.

Runtime

Execution and audit flow.

event
  -> idempotent ingestion
  -> typed workflow steps
  -> human approval gate
  -> action and notification
  -> ordered audit trace

The runtime owns retry, checkpoint, approval, and ordering behaviour. The stack includes FastAPI, Next.js, PostgreSQL, Redis, and Dramatiq.
