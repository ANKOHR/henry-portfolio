VerityDocs: how it works.

OCR, field provenance, deterministic validation, and review paths for document and invoice processing.

Problem

Extracted values need evidence

Values are difficult to trust when a reviewer cannot trace them to their source or see when financial arithmetic does not reconcile.

Constraints

Evidence and validation stay visible

Keep evidence attached to extracted fields. Use deterministic rules for financial arithmetic. Make mismatches visible for human review.

Design

Separate extraction from validation

OCR produces candidate fields with source provenance, then FIN-001 checks the financial totals.

Implementation

Provenance and a deterministic check

The build includes field-level provenance, confidence scoring, human review, and the FIN-001 calculation. No particular OCR engine or customer workflow is claimed here.

Failure modes

Surface uncertain and inconsistent inputs

A missing or uncertain field stays reviewable. A stated total that differs from subtotal plus VAT is surfaced as a failed check.

Testing

49 backend tests

The FIN-001 example passes for £8,000 plus £1,600 equalling £9,600, and flags a stated total of £9,900. The live demo is at the /demo endpoint.

Result

Evidence-backed document review

The system joins extracted values with source evidence and a deterministic arithmetic result.

Commercial applicability

Apply the pattern to a bounded document set

The service scopes the document set, required fields, validation rules, and review path before implementation.
